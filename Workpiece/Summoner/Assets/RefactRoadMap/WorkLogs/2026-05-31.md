# 2026-05-31 Work Log

## 1. Summary

오늘 작업은 Battle/Summon 영역의 상태이상 처리와 공격유형 실행 로직을 객체 단위로 분리하는 데 집중했다.
기존 전투 공식, 공격 대상 선택, 고양이 특수공격 흐름은 유지했다.

## 2. Main Changes

### 상태이상 로직 분리

- `Summon` 안에 있던 상태이상 적용/갱신/제거 로직을 `StatusEffectController`로 분리했다.
- `Summon`은 `IStatusEffectTarget`을 구현하고, 상태이상 객체가 필요한 최소 동작만 제공한다.
- 상태이상별 동작을 개별 클래스로 분리했다.
  - `PoisonStatusEffect`
  - `BurnStatusEffect`
  - `HealStatusEffect`
  - `UpgradeStatusEffect`
  - `CurseStatusEffect`
  - `StunStatusEffect`
  - `ShieldStatusEffect`
  - `LifeDrainStatusEffect`
  - `OnceInvincibilityStatusEffect`
- LINQ 사용을 제거하고 `foreach` 기반 흐름을 유지했다.

### 상태효과 인스턴스 생성 이름 정리

- `StatusEffectCreate`를 `StatusEffectInstanceCreate`로 이름 변경했다.
- 역할을 "상태효과 자체를 생성"이 아니라 "실제 적용할 상태효과 인스턴스 생성"으로 명확히 했다.
- 기존 `.meta` 파일을 함께 이동해 Unity GUID를 유지했다.

### 공격유형 실행 로직 분리

- `TargetedAttackStrategy`, `AttackAllEnemiesStrategy`, `ClosestEnemyAttackStrategy`에서 직접 처리하던 공격 효과 실행을 `IAttackEffect`로 분리했다.
- 공격유형별 효과 생성 파일을 추가/정리했다.
  - `TargetedAttackEffectInstanceCreate`
  - `AllEnemiesAttackEffectInstanceCreate`
  - `ClosestEnemyAttackEffectInstanceCreate`
- 각 공격 효과는 `AttackEffectApply()`로 실제 효과 적용을 수행한다.
- 각 공격 효과는 `BenefitEffectCheck()`로 이로운 효과 여부를 직접 판단한다.
- `IAttackStrategy`에도 `BenefitEffectCheck()`를 추가해 전략별 이로운 효과 판단을 공통 계약으로 맞췄다.

### Summon 중복 최소화

- `Summon`과 `Cat`에 반복되던 특수공격 인덱스 검사를 `SpecialAttackIndexCheck()`로 공통화했다.
- 공격 사용 가능 여부와 쿨타임 확인을 `AttackCanUse()`, `AttackCooldownCheck()`로 공통화했다.
- 공격 후 애니메이션, 색상 변경, 쿨타임 적용 흐름을 `AttackMotionPlay()`, `AttackCooldownApply()`로 공통화했다.
- `Cat`의 빈 `die()`, `takeDamage()` 오버라이드는 제거했다.
- `Cat.SpecialAttack()`은 기존 의도대로 가까운 적 공격 전략을 사용하며, 공격 직전에 `attackPower`를 `heavyAttakPower`로 바꿨다가 원복하는 흐름을 유지했다.

## 3. Important Behavior Kept

- 고양이 특수공격은 일반 공격과 같은 가까운 적 공격 로직을 사용한다.
- 고양이 특수공격은 공격력만 `heavyAttakPower`로 임시 변경해 더 큰 데미지를 준다.
- 전체 공격, 단일 공격, 가까운 적 공격의 대상 선택 방식은 유지했다.
- 상태이상별 데미지/회복/강화/보호막 적용 공식은 유지했다.
- 생성용 `switch`는 실행 로직이 아니라 인스턴스 생성 책임으로 남겼다.
