# 2026-05-30 작업 기록

## 1. 작업 요약

오늘은 리팩토링 문서 구조를 정리하고, 기존 로드맵에 흩어져 있던 완료 작업을 기능별로 요약했다.

- 로드맵 문서와 WorkLog의 역할을 분리했다.
- 기존 완료 작업을 GameSystem, StorySystem, BattleCore, BattleContent 기준으로 다시 묶었다.
- MCP 테스트 timeout과 batchmode 실패 같은 미검증 항목을 QA 추적 대상으로 남겼다.

역할:
- DevAgent 작업 기록. QAAgent 역할 전환 아님.

---

## 2. 작업 배경

이 작업을 진행한 이유는 다음과 같다.

- 기존 문제:
  - 로드맵 문서마다 과거 변경 기록이 길게 쌓여 현재 상태와 다음 작업을 찾기 어려웠다.
  - 완료 작업과 미검증 작업이 섞여 있어 새 작업자가 프로젝트 상태를 빠르게 파악하기 어려웠다.
- 작업 목적:
  - 로드맵은 현재 상태와 다음 작업 중심으로 유지한다.
  - 과거 작업 이력은 WorkLogs로 분리한다.
  - 검증하지 못한 항목은 완료로 보지 않고 QAReports에서 추적한다.
- 관련 기능:
  - GameSystem: 저장, 이어하기, 스테이지 선택
  - StorySystem: 대사, 입력, 씬 이동
  - BattleCore: 턴, 공격, 상태이상, 승패 판정
  - BattleContent: 소환, 배치, 적 AI

## 3. 작업 내용

### 3.1 로드맵과 작업 로그 역할 분리

#### 변경 전

기존에는 다음과 같은 문제가 있었다.

- 로드맵에 상세 변경 기록이 계속 누적됐다.
- 현재 해야 할 작업과 이미 끝난 작업을 구분하기 어려웠다.

#### 변경 후

다음과 같이 정리했다.

- 로드맵은 현재 상태, 목표, 활성 작업, 완료 기준 위주로 구성했다.
- 과거 상세 기록은 WorkLogs로 옮겼다.
- 파일 상태 추적 문서는 현재 파일 상태와 기능 연결 상태를 중심으로 정리했다.

#### 관련 파일

- `Assets/RefactRoadMap`
- `Assets/RefactRoadMap/WorkLogs`

### 3.2 기존 완료 작업 요약 이관

#### 변경 전

기존에는 다음과 같은 문제가 있었다.

- GameSystem, StorySystem, BattleCore, BattleContent 완료 이력이 여러 문서에 흩어져 있었다.
- 테스트가 끝난 항목과 timeout으로 막힌 항목이 같은 수준으로 보일 수 있었다.

#### 변경 후

다음과 같이 정리했다.

- GameSystem은 저장 접근과 이어하기 판단 흐름 중심으로 요약했다.
- StorySystem은 View 이름 정리, 대사 진행, 스토리 씬 이동, Stage 입력 공통화 중심으로 요약했다.
- BattleCore와 BattleContent는 전투 규칙과 소환 콘텐츠의 책임 분리 후보를 요약했다.
- timeout이나 transport 문제로 검증하지 못한 항목은 미검증 상태로 남겼다.

#### 관련 파일

- `Assets/RefactRoadMap/01_GameSystemRoadmap.md`
- `Assets/RefactRoadMap/02_StorySystemRoadmap.md`
- `Assets/RefactRoadMap/03_BattleCoreRoadmap.md`
- `Assets/RefactRoadMap/04_BattleContentRoadmap.md`

## 5. 발생한 문제와 해결

### 문제

일부 MCP EditMode/PlayMode 테스트와 재컴파일 요청이 timeout 또는 transport 문제로 완료되지 않았다.

### 원인

Unity Editor 또는 MCP 연결 상태가 불안정했다. batchmode 실행도 같은 프로젝트를 여는 Unity 인스턴스가 있어 중단됐다.

### 해결

검증하지 못한 항목을 완료 처리하지 않고 QAReports와 WorkLogs에 남겼다. 이후 검증은 batchmode가 아니라 MCP `recompile_scripts`와 `run_tests` 기준으로 진행하기로 했다.
