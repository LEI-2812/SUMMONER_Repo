# Dev Log

날짜별 작업 결정과 완료 요약만 짧게 남긴다.

## 작성 형식

```md
# YYYY-MM-DD Dev Log

## 작업 정책 변경

- 무엇을 왜 바꿨는가

## 기능 완료

- 어떤 기능이 어떤 기준으로 완료됐는가
- 확인한 테스트나 QA

## 남은 작업

- 다음에 이어갈 구체 항목
```

## 기록하지 않는 것

- 긴 로그
- 긴 파일 목록
- MCP timeout 상세 반복
- 현재 판단에 필요 없는 과거 이력
- 작업명이나 티켓 ID를 붙인 별도 파일

## 운영 기준

- 파일명은 `YYYY-MM-DD.md`만 사용한다.
- 구조 결정, 기능 완료, QA 완료, 작업 정책 변경만 기록한다.
- 간단한 질문, 단순 파일 확인, 기능 개발 중간 단계는 기록하지 않는다.
