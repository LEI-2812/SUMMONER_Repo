# Dev Log

날짜별 작업 결정과 완료 요약만 짧게 남긴다.
사소한 일은 기록하지 않는다.

## 작성 형식

```md
# YYYY-MM-DD Dev Log

## 작업 정책 변경

- 무엇을 왜 바꿨는가. 작업 하나당 1~3줄.

## 기능 완료

- 어떤 기능이 어떤 기준으로 완료됐는가. 작업 하나당 1~3줄.
- 확인한 테스트나 QA는 핵심 결과만 쓴다.

## 남은 작업

- 다음에 이어갈 구체 항목
```

## 기록하지 않는 것

- 긴 로그
- 긴 파일 목록
- MCP timeout 상세 반복
- 현재 판단에 필요 없는 과거 이력
- 작업명이나 티켓 ID를 붙인 별도 파일
- 사소한 질문 답변
- 단순 파일 확인
- 문구만 바꾼 수정
- 기능 개발 중간 시행착오
- active 문서 상태만 맞춘 변경

## 운영 기준

- 파일명은 `YYYY-MM-DD.md`만 사용한다.
- 구조 결정, 기능 완료, QA 완료, 작업 정책 변경만 기록한다.
- 하나의 작업은 1~3줄을 기본으로 한다.
- 사소한 항목을 기록해야 할지 애매하면 기록하지 않는다.
- 오래된 날짜별 원본은 `.codex/archive/dev-log/`로 옮긴다.
- 과거 전체 요약 인덱스는 `.codex/records/history-summary.csv`에 둔다.
