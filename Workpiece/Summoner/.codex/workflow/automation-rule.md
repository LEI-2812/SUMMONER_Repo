# Automation Rule

이 문서는 에이전트 자동 루프 기준을 정의한다.

자동 루프의 실행 주체는 PowerShell 스크립트가 아니라 Codex다.
스크립트는 상태 점검이나 보조 실행에만 사용하고, 실제 에이전트 판단과 작업은 Codex가 수행한다.

## 시작 명령

사용자가 아래처럼 말하면 자동 루프를 시작한다.

- `자동 루프 시작`
- `자동으로 계속 진행해`
- `에이전트 자동화 진행해`
- `끝까지 자동으로 진행해`

## 기본 루프

```text
agent-status.md 확인
→ Ready 에이전트 찾기
→ 해당 role 문서 하나만 확인
→ 실제 작업 수행
→ 결과를 필요한 workflow 문서에 기록
→ 기능 개발 완료, QA 완료, 구조 결정, 작업 정책 변경이면 dev-log 갱신
→ 사용자에게 다음 작업과 승인 필요 여부를 보고
→ 다음 에이전트 하나만 Ready로 변경
→ 반복
```

## 에이전트별 실행 기준

### FlowAgent

세부 기준은 `.agents/roles/FlowAgent.md`를 따른다.
자동 루프에서는 아래만 추가로 지킨다.

- 기능 목표, 설계 품질 기준, QA 깊이 기준을 먼저 정리한다.
- 다음 `Ready` 에이전트를 하나만 남긴다.
- DEV 완료는 `.codex/records/dev-records.csv`에 한 줄 추가한다.
- 기능 개발 완료, QA 완료, 구조 결정, 작업 정책 변경이면 dev-log를 갱신한다.

### DevAgent

세부 기준은 `.agents/roles/DevAgent.md`를 따른다.
자동 루프에서는 아래만 추가로 지킨다.

- 일반 코드 변경은 승인 대기 없이 적용할 수 있다.
- 위험 작업은 적용하지 않고 `Blocked` 또는 `PermissionRequired`로 멈춘다.
- 작은 private 리팩터링은 QAReviewAgent로 자동 전환하지 않는다.
- public API와 런타임 의미가 유지되고 컴파일/관련 테스트가 통과하면 FlowAgent로 돌려보낸다.
- QA 호출 조건에 해당할 때만 `QA필요`로 전환한다.

### QAReviewAgent

세부 기준은 `.agents/roles/QAReviewAgent.md`를 따른다.
자동 루프에서는 아래만 추가로 지킨다.

- QA 깊이 기준 일부만 확인하고 `Pass`로 기록하지 않는다.
- Unity가 메인 프로세스가 아니어서 발생한 Test Time exceeded는 코드 실패로 보지 않는다.
- 테스트 생성을 위해 씬, 에셋, 저장 데이터 구조를 바꿔야 하면 멈춘다.
- QA 완료는 `.codex/records/qa-records.csv`에 한 줄 추가한다.

## 중단 조건

아래 조건에서는 자동 루프를 멈춘다.

- `agent-status.md`에 `Ready` 에이전트가 없다.
- `Ready` 에이전트가 둘 이상이다.
- 상태가 `Blocked`, `PermissionRequired`, `WaitingApproval`이다.
- 파일 삭제, 씬 변경, 에셋 삭제 또는 대량 이동이 필요하다.
- 저장 데이터 구조 변경이 필요하다.
- 외부 API, 유료 서비스, 클라우드 연결이 필요하다.
- 테스트나 도구 오류가 반복되어 코드 문제인지 판단할 수 없다.
- 사용자가 중단을 요청한다.

## 금지

- 실제 작업 없이 상태만 넘기지 않는다.
- 여러 에이전트를 동시에 `Ready`로 두지 않는다.
- 검증하지 않은 내용을 `Pass`로 기록하지 않는다.
- 기능 개발 중간 결과를 `Pass`로 기록하지 않는다.
- 사전에 정한 QA 깊이 기준 일부만 확인하고 `Pass`로 기록하지 않는다.
- 기능 완료 조건을 만족했는데 남은 개발을 구체적으로 기록하지 않고 DevAgent 개발을 계속하지 않는다.
- 다음 작업을 내부 문서에만 남기고 사용자 보고에서 생략하지 않는다.
- 날짜별 작업 기록이 필요한 구조 결정이나 완료 작업을 dev-log 없이 끝내지 않는다.
- 간단한 질문 답변, 단순 파일 확인, 기능 개발 중간 단계를 dev-log에 과하게 누적하지 않는다.
- 자동 생성 테스트는 기능 완료 조건을 확인하는 최소 범위를 넘지 않는다.
- 최소 범위는 기능 흐름을 실제로 증명할 수 있는 깊이를 포함해야 한다.
- 턴 진행 기능은 플레이어 턴과 적 턴의 2~3회 왕복 없이 Pass 처리하지 않는다.
- Unity가 메인 프로세스가 아니어서 발생한 Test Time exceeded를 코드 이슈처럼 상세 누적하지 않는다.
- 테스트 생성을 이유로 씬, 에셋, 저장 데이터 구조를 임의 변경하지 않는다.
- PowerShell runner를 핵심 자동화로 사용하지 않는다.
- 권한 요청이나 위험 작업을 임의로 우회하지 않는다.

## 보조 스크립트 기준

`.codex/scripts/agent-workflow-run.ps1`는 상태 전환 실험이나 점검용 보조 도구다.

자동 루프의 실제 진행은 이 스크립트가 아니라 Codex가 수행한다.
