# Automation Rule

자동 루프를 명시적으로 요청했을 때만 읽는다.

## 현재 사용자 지시

- 반복되는 유지보수 리팩토링은 중단 없이 계속 진행한다.
- DevAgent는 Change Proposal과 적용 예정 diff를 보여준 뒤, 같은 기능 슬라이스 안의 저위험 반복 작업은 별도 승인 대기 없이 적용한다.
- 아래 중단 조건에 해당하는 위험 작업은 자동 진행하지 않는다.

## 흐름

```text
Ready 확인
-> 현재 Ready 역할 문서 하나만 읽기
-> CoordinatorAgent가 기능 슬라이스, 완료조건, 호출 대상 확정
-> CoordinatorAgent가 사용자에게 보여줄 일과 바로 넘길 일을 구분
-> DevAgent가 적용 예정 diff와 완료조건을 제시
-> 저위험 반복 작업이면 별도 승인 대기 없이 기능 슬라이스 안에서 구현
-> 완료조건을 만족하면 같은 기능의 추가 미세정리를 이어가지 않음
-> 위험 작업이면 진행 승인 확인 후 구현
-> 필요한 경우 CoordinatorAgent가 VerificationAgent 호출
-> 필요한 경우 CoordinatorAgent가 DocumentationAgent 호출
-> 필요한 경우 CoordinatorAgent가 ReleaseAgent 호출
-> active 문서에는 현재 슬라이스와 다음 호출 대상만 즉시 갱신
-> 다음 작업 3줄 보고
```

## 호출 기준

- DevAgent는 기본 개발 흐름이다.
- DevAgent는 코드 변경 전 적용 예정 diff와 완료조건을 보여준다.
- 반복되는 저위험 리팩토링은 사용자의 현재 자동 진행 지시를 승인으로 보고 이어서 적용한다.
- 완료조건을 만족하면 같은 기능 슬라이스를 닫고 다음 후보로 이동한다.
- 위험 작업은 적용 예정 diff와 별도 진행 승인을 필요로 한다.
- CoordinatorAgent는 문서 갱신과 다음 에이전트 인계를 사용자 승인 없이 처리한다.
- CoordinatorAgent는 코드 diff 승인, 위험 작업, 제품 판단이 필요한 결정만 사용자에게 보여준다.
- 문서 상태 기록은 사용자 진행 승인 없이 바로 수행한다.
- VerificationAgent는 review mode 또는 QA mode가 필요한 위험 변경/기능 게이트에서만 호출한다.
- DocumentationAgent는 기능 완료, handoff, release note, 큰 결정 기록 때만 호출한다.
- ReleaseAgent는 릴리즈/배포/버전 정리 요청 때만 호출한다.

## 검증 원칙

- 작은 변경마다 EditMode/PlayMode를 반복하지 않는다.
- 검색/컴파일로 닫히는 변경은 테스트를 반복하지 않는다.
- EditMode는 순수 로직/데이터/전략/예측 기능 게이트에서 실행한다.
- PlayMode는 런타임 객체 연결이 바뀐 기능 게이트에서만 실행한다.
- MCP 오류는 코드 실패와 분리한다.

## 중단 조건

- Ready 에이전트가 없거나 둘 이상
- Ready 작업에 완료조건이 없음
- DevAgent가 적용 예정 diff 없이 코드 변경하려는 경우
- 위험 작업인데 사용자가 제시된 diff 진행을 승인하지 않은 경우
- 도메인 변경
- 사용자 승인 필요한 위험 작업
- 테스트/도구 오류가 반복되어 코드 문제와 구분이 필요한 경우
- 사용자가 중단 요청

## 하지 말 것

- 실제 개발 없이 상태만 넘기기
- 고정 파이프라인처럼 모든 에이전트를 순서대로 호출하기
- 네이밍 정리만 계속 다음 작업으로 고르기
- 완료조건을 만족한 기능을 계속 확장하기
- 작은 변경마다 기존 기능 전체 테스트하기
- DocumentationAgent를 상시 기록 담당으로 붙이기
- 완료 이력을 active 문서에 쌓기
- 검증하지 않은 내용을 Pass로 기록하기
