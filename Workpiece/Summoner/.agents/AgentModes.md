# Agent Modes

## 1. User-led Mode

사용자가 대화 중이고 직접 판단하려는 경우 적용한다.
에이전트는 보조 역할을 한다.

### 진행 방식

1. 관련 파일과 현재 흐름을 먼저 확인한다.
2. 수정 대상 파일, 수정 이유, 예상 변경 범위를 설명한다.
3. 실제 코드 변경 전 diff 또는 변경 전/후 코드를 제안한다.
4. 사용자가 `적용해`, `수정해`, `진행해`, `그렇게해`처럼 명확히 승인한 뒤에만 수정한다.
5. 수정 후 가능한 가장 작은 검증을 실행한다.
6. 변경 내용, 검증 결과, 남은 이슈를 짧게 보고한다.

## 2. Delegated Development Mode

사용자가 `자동으로 진행해`, `끝까지 해줘`, `알아서 이어가`, `자리 비움`처럼 명확히 위임한 경우 적용한다.
에이전트는 사용자를 대신해 작은 개발 단위를 계속 이어간다.

### 진행 방식

1. FlowAgent가 작업 범위와 중단 조건을 정리한다.
2. DevAgent가 원인이 명확한 작은 개발 단위를 선택한다.
3. DevAgent가 기존 흐름을 유지하면서 수정한다.
4. TestAgent가 컴파일과 최소 테스트를 실행한다.
5. QAAgent가 핵심 동작이 실제로 돌아가는지 Smoke Check를 한다.
6. ReviewAgent가 변경 범위와 유지보수 리스크를 짧게 확인한다.
7. FlowAgent가 결과와 다음 작업을 정리한다.

### 자동 진행 가능

- 원인이 명확한 작은 버그 수정
- 기존 기능 복구
- 테스트 추가 또는 기존 테스트 보강
- 개발 결과에 대한 Smoke Check
- 필요한 최소 문서 갱신

### 자동 진행 금지

- 대규모 구조 변경
- 추측성 리팩토링
- 씬, 프리팹, 에셋 삭제 또는 대량 이동
- 저장 데이터 구조 변경
- 외부 API, 유료 서비스, 클라우드 연결
- 개발 없이 QA 문서만 계속 작성하는 작업

## 3. Smoke Check Rule

QAAgent는 깊은 QA를 하지 않는다.
개발 결과가 사용자의 기대 흐름대로 돌아가는지만 짧게 확인한다.

확인 기준:

- 기능이 실행되는가
- 핵심 버튼이나 입력이 동작하는가
- 저장/로드 같은 핵심 결과가 깨지지 않았는가
- Console에 명확한 게임 코드 오류가 있는가
- MCP 오류와 게임 코드 오류가 분리되었는가

결과는 `Pass`, `Needs Fix`, `Blocked` 중 하나로 기록한다.

## 4. 자동 중단 조건

- 수정 대상이 3개 파일을 초과하고 사용자가 허용하지 않았다.
- 씬, 프리팹, 에셋 삭제 또는 대량 이동이 필요하다.
- 저장 데이터 구조가 바뀐다.
- 요구사항 해석이 불명확하다.
- 컴파일 실패가 2회 이상 반복된다.
- 테스트 실패가 코드 문제인지 환경 문제인지 구분되지 않는다.
- 같은 MCP 오류가 2회 반복된다.

## 5. 위험 작업

아래 작업은 어떤 모드에서도 바로 진행하지 않는다.

- 파일 삭제
- 씬 변경
- 에셋 삭제 또는 대량 이동
- 저장 데이터 구조 변경
- 외부 API 또는 유료 서비스 연결
- 대규모 폴더 구조 변경
